## 製品概要
### 背景(製品開発のきっかけ、課題等）
自炊をしようと食材を買っても、仕事や学校で疲れた日は「今日は無理」となり、予定が崩れます。崩れた日が続くと、冷蔵庫の食材は期限を過ぎて捨てることになり、「また無駄にした」という罪悪感も残ります。

既存の食材管理アプリは、元気なときに献立を立てて在庫を管理するための道具です。でも食材がだめになるのは、まさに疲れて管理どころではない日です。

### 製品説明（具体的な製品の説明）
疲れて自炊の予定が崩れた日に、捨てそうな食材を救う**行動を1つだけ**届けるフードロス削減Webアプリです。ログインはなく、端末ごとのIDでデータを分けます。

1. 買い物のあとにレシートを1回撮るだけで、品目と購入日を読み取り、チェックして冷蔵庫の中身を登録します（自分で選んだ品名は覚えて、次から自動で当てます）
2. 早めに使いたい食材がある日だけ、決めた時刻（初期18:00）に「今日、作れそう？［作る／無理］」と通知します。通知を見逃しても、ホームの一番上に同じ問いかけが出ます
3. 「無理」を押すと、30秒でできる行動を1つだけ返します（例：「豚こまを、袋のまま冷凍庫へ」）
4. その夜（初期21:30）に「豚こま、冷凍庫に入れた？」と聞きます。「あとで」なら1回だけもう一度。通知は1日に多くても3回です
5. ホームの小さなカードで「今週 守れた 3品」と、守れたことを見せます（「捨てた」とは書きません）

### 特長
#### 1. 崩れた日にすることは「ボタン1つ」と「30秒の行動1つ」だけ
献立も計画もいりません。救済行動は、袋ごと冷凍する、など疲れていてもできることだけに絞り、2つ目の行動は出しません。在庫がずれていたときのために「豚こまはもう使った」「もう残っていなかった」を必ず置いています。Androidでは通知のボタンから、アプリを開かずに答えられます。

#### 2. レシートを撮るだけで在庫ができる
Gemini API でレシートの品名・JANコード・購入日を文字起こしし、食材への当てはめはコードで行います（キーワード照合、調味料の除外、学習した対応）。長いレシートは自動で切り出し・分割し、AI が使えないときは端末内のOCR（Tesseract.js）に切り替わります。

#### 3. 罪悪感を与えず、安全を断言しない
損失額も「捨てた」という言葉も出さず、間に合わなかった品がある週も「守れた」を先に出します。期限は購入日からの推定で、USDA FoodKeeper と農林水産省の資料をもとに短め（安全側）に取り、「まだ食べられます」とは言いません。

### 解決出来ること
- 疲れて自炊できなかった日に、食材を捨てずに済む（冷凍・すぐ食べられる形で救う）
- 「何を作るか考える」「在庫を管理する」負担なしに、食材の期限を意識できる
- 崩れた日が続いても「今週も守れた」と実感でき、自炊を続けやすくなる

### 今後の展望
- 本番環境へのデプロイと、ログインへの対応（今は端末ごとのID）
- パッケージの期限の読み取り（今はレシートの購入日と食材ごとの目安で推定）
- 食材表・料理表の拡充と、メーカー公式の保存方法への差し替え

### 注力したこと（こだわり等）
* **判定はコード、LLMは文字起こしだけ。** 日数・期限・どの食材を救うか・どの料理を勧めるか・品名がどの食材かは、すべてコードで判定し、結果がブレないようにしました
* **出典のある目安。** 冷蔵日数は USDA FoodKeeper、冷凍期間は農林水産省「2〜3週間」をもとにし、食い違うときは短い方に合わせています。アプリ内の「目安と出典」画面で根拠を確認できます
* **時間に関わる処理はサーバー側。** 端末ごとに決めた時刻の問いかけ、冷凍のリマインド、「あとで」の1時間後の再通知（1回だけ）をサーバーのスケジューラーで動かし、画面を開いていなくても Webプッシュで届きます
* **試用の記録。** 通知から行動までの秒数・タップ数・どこから答えたかを記録し、開発者メニュー（アプリ名を3秒長押し）で平均の表示とCSVの書き出しができます
* **実物のレシートで検証。** ドラッグストアのレシートで「麻婆豆腐の素」を豆腐と取り違えないよう、長いキーワードを先に照合し、調味料の行は生鮮食材に当てないようにしました。照合の試験は `python -m unittest` で確かめられます

## 開発技術
### 活用した技術
#### API・データ
* Gemini API（`gemini-3.5-flash-lite`。混雑時は別のモデルに自動で切り替え）：レシートの文字起こし
* Web Push（VAPID）：問いかけ・冷凍のリマインドの通知（Androidでは通知のボタンで答えられる）
* [USDA FoodKeeper](https://www.foodsafety.gov/keep-food-safe/foodkeeper-app)、[農林水産省「ホームフリージングする際の注意点」](https://www.maff.go.jp/j/heya/sodan/1810/01.html)：保存の目安の出典
* クックパッド：料理の提案から検索結果ページへのリンク（内容の取り込みはしない）

#### フレームワーク・ライブラリ・モジュール
* Python 3（標準ライブラリの HTTP サーバー）、`google-genai`、`pywebpush`、`cryptography`
* 素の HTML / CSS / JavaScript（ビルド不要）、Service Worker、PWA
* Tesseract.js（予備のOCR）

#### デバイス
* スマートフォン（Android / ホーム画面に追加した iPhone）
* PC・タブレットのブラウザ

### 独自技術
#### ハッカソンで開発した独自機能・技術
* 期限の推定・救済行動の選択・料理の提案・今週の集計の判定ロジック：[`server/logic.py`](server/logic.py)
* レシートの品名を食材表に当てはめる照合（正規化・学習した対応・キーワード・除外語・候補）：[`server/ocr_match.py`](server/ocr_match.py)、試験：[`tests/`](tests/)
* 端末ごとのデータ、時刻を進められるデモ用の時計、通知のスケジューラー、試用の記録：[`server/app.py`](server/app.py)
* 通知のボタンで答えられる Service Worker：[`web/sw.js`](web/sw.js)
* レシート画像の自動切り出し・分割と、AI → 端末内OCR → デモ用データの順に切り替える読み取り：[`web/app.js`](web/app.js)
* 出典つきの食材表・料理表：[`data/`](data/)

## 動かし方
```
pip install -r requirements.txt
cp .env.example .env          # GEMINI_API_KEY と DEBUG_PASSWORD を入れる（キーがなくても端末内のOCRで動く）
python -m server.app          # http://localhost:8000
```
ホームのアプリ名を3秒長押しすると開発者メニューが開き、時刻を進めてデモシナリオを再現できます。スマホから使う方法や仕様の詳細は [`CLAUDE.md`](CLAUDE.md) にあります。
