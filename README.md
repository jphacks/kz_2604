## 製品概要
### 背景(製品開発のきっかけ、課題等）
自炊をしようと食材を買っても、仕事や学校で疲れた日は「今日は無理」となり、予定が崩れます。崩れた日が続くと、冷蔵庫の食材は期限を過ぎて捨てることになり、「また無駄にした」という罪悪感も残ります。

既存の食材管理アプリは、元気なときに献立を立てて在庫を管理するための道具です。でも食材がだめになるのは、まさに疲れて管理どころではない日です。

### 製品説明（具体的な製品の説明）
自炊の予定が崩れた瞬間に、**考えなくていい行動を1つだけ**届けて、食材と自分の食生活を救うWebアプリです。

1. 買い物のあとにレシートを1回撮るだけで、品目と購入日を読み取って冷蔵庫の中身を登録します
2. 早めに使いたい食材がある日だけ、18時に「今日、作れそう？［作る／無理］」と通知します
3. 「無理」を押すと、30秒でできる行動を1つだけ返します（例：「豚こまが残っていたら、袋のまま冷凍庫へ」）
4. その夜21:30に「豚こま、冷凍した？」と1回だけ確かめます
5. ホームの小さなカードで「今週 捨てたもの 0 ／ 守れた 2回」と、守れたことを見せます

### 特長
#### 1. 崩れた日にすることは「ボタン1つ」と「30秒の行動1つ」だけ
献立も計画もいりません。救済行動は、袋ごと冷凍する・パックのまま冷奴にする、など疲れていてもできることだけに絞っています。文は必ず「〜が残っていたら」と条件付きにして、在庫がずれていても嘘にならないようにしています。

#### 2. レシートを撮るだけで在庫ができる
Gemini API でレシートの品名と購入日を文字起こしし、食材への当てはめはコードで行います。長いレシートは自動で切り出し・分割し、AI が使えないときは端末内のOCR（Tesseract.js）に切り替わります。

#### 3. 罪悪感を与えず、安全を断言しない
損失額は出さず、捨てたものがある週も「守れたもの」を先に出します。期限は購入日からの推定で、USDA FoodKeeper と農林水産省の資料をもとに短め（安全側）に取り、「まだ食べられます」とは言いません。

### 解決出来ること
- 疲れて自炊できなかった日に、食材を捨てずに済む（冷凍・すぐ食べられる形で救う）
- 「何を作るか考える」「在庫を管理する」負担なしに、食材の期限を意識できる
- 崩れた日が続いても「今週も守れた」と実感でき、自炊を続けやすくなる

### 今後の展望
- 本番環境へのデプロイと、複数ユーザー・ログインへの対応
- パッケージの期限の読み取り（今はレシートの購入日と食材ごとの目安で推定）
- 食材表・料理表の拡充と、メーカー公式の保存方法への差し替え
- 冷凍したものを使い切るまでのフォロー

### 注力したこと（こだわり等）
* **判定はコード、LLMは文字起こしだけ。** 日数・期限・どの食材を救うか・どの料理を勧めるか・品名がどの食材かは、すべてコードで判定し、結果がブレないようにしました
* **出典のある目安。** 冷蔵日数は USDA FoodKeeper、冷凍期間は農林水産省「2〜3週間」をもとにし、食い違うときは短い方に合わせています。アプリ内の「目安と出典」画面で根拠を確認できます
* **時間に関わる処理はサーバー側。** 18時の問いかけ、21時の締め切り、21:30の冷凍のリマインド、「まだ」の1時間後の再通知（上限2回）をサーバーのスケジューラーで動かし、画面を開いていなくても Webプッシュで届きます
* **実物のレシートで検証。** ドラッグストアのレシートで「麻婆豆腐の素」を豆腐と取り違えないよう、調味料・加工品の行を除くようにしました

## 開発技術
### 活用した技術
#### API・データ
* Gemini API（`gemini-3.5-flash-lite`。混雑時は別のモデルに自動で切り替え）：レシートの文字起こし
* Web Push（VAPID）：18時の問いかけ・冷凍のリマインドの通知
* [USDA FoodKeeper](https://www.foodsafety.gov/keep-food-safe/foodkeeper-app)、[農林水産省「ホームフリージングする際の注意点」](https://www.maff.go.jp/j/heya/sodan/1810/01.html)：保存の目安の出典
* クックパッド：料理の提案から検索結果ページへのリンク（内容の取り込みはしない）

#### フレームワーク・ライブラリ・モジュール
* Python 3（標準ライブラリの HTTP サーバー）、`google-genai`、`pywebpush`、`cryptography`
* 素の HTML / CSS / JavaScript（ビルド不要）、Service Worker、PWA
* Tesseract.js（予備のOCR）

#### デバイス
* スマートフォン（Android / ホーム画面に追加した iPhone）
* PC・タブレットのブラウザ

### 独自技術
#### ハッカソンで開発した独自機能・技術
* 期限の推定・救済行動の選択・料理の提案・今週の集計の判定ロジック：[`server/logic.py`](server/logic.py)
* レシートの品名を食材表に当てはめる照合（正規化・あいまい一致・調味料の除外）：[`server/ocr_match.py`](server/ocr_match.py)
* 時刻を進められるデモ用の時計と、通知のスケジューラー：[`server/app.py`](server/app.py)
* レシート画像の自動切り出し・分割と、AI → 端末内OCR → デモ用データの順に切り替える読み取り：[`web/app.js`](web/app.js)
* 出典つきの食材表・料理表：[`data/`](data/)

## 動かし方
```
pip install -r requirements.txt
cp .env.example .env          # GEMINI_API_KEY を入れる（なくても端末内のOCRで動く）
python -m server.app          # http://localhost:8000
```
画面下の「デモ操作」から、時刻を進めてデモシナリオを再現できます。スマホから使う方法や仕様の詳細は [`CLAUDE.md`](CLAUDE.md) にあります。
